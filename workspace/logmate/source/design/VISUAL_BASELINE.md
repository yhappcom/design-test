## Baseline selection gate

A candidate can become active baseline only when:
1. it is one of a documented candidate round;
2. it uses current product semantics;
3. it includes Home plus Add Flight/View Logbook transfer evidence;
4. coordinator recommends it or explains why owner preference overrides;
5. owner explicitly selects it.

After selection this file must record:
- Baseline ID
- selected candidate
- exact image/prototype reference
- typography roles
- color roles
- surface/container grammar
- spacing/alignment grammar
- icon/navigation grammar
- numeric/data grammar
- global invariants
- screen-specific exceptions
- rejected alternatives
- open validation items
- canonical promotion status

Until then, visual work is candidate exploration only.


## Owner-confirmed global invariants before baseline selection

These invariants constrain every future candidate even though no full visual baseline is selected yet.

### Language
- App UI is English-only.
- No Korean UI/localized product-string variant is planned.
- Design review boards may use Korean annotation outside device frames, but all rendered app UI inside device frames must be English.

### Primitive / container language
- Do not expose stock Flutter/Material box/card visual grammar as the LogMate identity.
- Do not use repeated rounded cards or filled boxes to create hierarchy.
- Prefer authored hierarchy from typography, alignment, spacing, datum/rule systems and custom interaction primitives.
- Necessary interactive boundaries are allowed; generic stock-card appearance is not.
